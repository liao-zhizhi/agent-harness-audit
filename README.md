# 执行层审计：AI Agent 的"假完成"

> Agent 说"任务完成"时，你拿到的是一句**声称**，不是一次**观察**。
> 这套东西审计的是：**你的 Harness 有没有能力报出失败。**

---

## 30 秒版

**要求**：Python 3.8+，需要 PATH 上有 `bash`（Demo 用 `bash -c` 取两个退出码）。
原生 Windows 没有 bash，请用 WSL / Git Bash / Linux / macOS。

**已在 3.8.20 / 3.9.25 / 3.11 / 3.12.3 / 3.13.18 上实跑验证**（全部退出码 0）；
3.7 会明确报"需要 3.8+"而不是崩栈。

```bash
python3 agent_audit_demo.py      # 退出码 0 = 全部符合预期
```

```
M1  masked failure (the defect)
  agent saw    : exit 0
  command said : exit 1
  agent report : "Task Completed Successfully"
  verdict      : INVALID
```

命令失败了。Harness 把输出管过 `cat`，退出码变成 `cat` 的（永远 0）。Agent 读到 0，报成功——**它没撒谎，
它读的信号从出生起就不可能说别的话**。

审计器的判词是 `INVALID`：不是"任务失败"，是"**这次成功不是证据**"。

## 核心结论（三句）

1. **判据**：一个成功信号，只有在**存在某次执行会让它报失败**时才是"检查"，否则只是"装饰"——不管它
   看起来多正式。
2. **四值判词**：`PASS` / `FAIL` / `INVALID` / `NOT RUN`。`INVALID ≠ PASS`，`NOT RUN ≠ FAIL`。
   没有 `INVALID` 的审计不会报出异常多的 `INVALID`，**它会报出异常多的 `PASS`**。
3. **迁移是有损的**：源框架的三件仪器里，可失败条件原样搬、同源检测**退化**成搜索、变异**变强**了，
   而**重算彻底丧失**——正是这一件损失，把度量分母从工作负载逼成了公开探针套件。

## Demo 证明了两件事，不是一件

**一、它能抓出掩盖。**

四个变异体，期望判词事先写死，**4/4 符合预期**：

| 变异体 | 期望 |
|:--|:--|
| 掩盖失败 | `INVALID` |
| 同一命令，修好传输 | `PASS` |
| 命令真的成功 | `PASS` |
| 掩盖且 Agent 判断也错 | `INVALID` |

**二、它自己能被证伪。**

随后我们**变异了审计器本身**，四个变异里有一个**没有变异成功**：

| 对审计器的变异 | 效果 | 抓到 |
|:--|:--|:--|
| 主判断改 `if False:` | **无变化**，第二道判断仍接住 | 否，且正确 |
| 恒返回 `PASS` | 判据被移除 | 是 |
| 恒返回 `INVALID` | 恒假，一样无用 | 是 |
| 用 `m=$?` 代替 `PIPESTATUS` | 见证被冲掉 | 是 |

第一行是关键：**我们的变异测试本身是坏的。** 把主判断关掉之后，审计仍然"4/4 通过"——绿的结果，正确，
且毫无意义。它只说明了没被改过的审计器像没被改过的审计器。

> **一个存活的变异体，只有在它最初是活的时候才有信息量。**

推论：**变异测试必须断言"变异改变了可观察行为"，而不只是"套件跑过了"。**

## 三个度量

| 度量 | 定义 | 方向 |
|:--|:--|:--|
| Execution Integrity Rate (EIR) | 必须非零退出的命令，真的报出了失败 | 越高越好 |
| State Drift Rate (SDR) | 旧产物被消费掉 | **越低越好（反向）** |
| Mutation Resistance (MR) | 违反护栏的输入被拒绝 | 越高越好 |

两条纪律：

- **分母是探针套件，不是真实流量。** 不是选择，是"重算丧失"推出来的必然。
- **没注入探针就是 `undefined`，不是 `1.0`。** 把未测量报成满分，就是 `INVALID → PASS` 的度量版本；
  而且因为 SDR 反向，把三项平均的仪表盘会把易漂移的 Harness 显示成健康。

## 边界（请连同上面一起引用）

- **不主张发生率。** 所有外部百分比都是别人的测量、别人的分母，只作动机引用。主张的是**机制存在且可
  检测**，不是**发生频率**。
- **不是防护。** 每个方法都是事后或事中识别，没有一个能让 Agent 变正确。
- **机制不是新发现。** "Agent 从同一个误读里派生动作和校验"，2026 年产业评测已用散文说过。我们主张的
  是**方法迁移**，不是机制。
- **探针套件无法自证充分。** 这是最尖的漏洞，而且框架内部修不了——因为重算已经没了。论文 §9 明写。
- **审计者在被审计系统内部。** 我们抓到了自己三处写错、且都**报告成功**的检查，一个没变异成功的变异
  测试，以及一个方向反了的引用数字。详见 `EXECUTIVE_BRIEF.md` §5 与论文 §7.3、§7.4、§8.1。
- **Demo 的探针只覆盖简单管道环境。** 它在一个被插桩的管道上读判词，这个插桩本身也是对**单次执行**的
  一次探针。我们用论文里没出现的命令攻击过它，抓到三个缺陷（命令自带管道时的假阴性、无尾换行时的解析
  失败、非 UTF-8 输出时**直接崩溃而非给出判词**），均已修复并记录在论文 §9。抽样中信号、trap、
  `set -e`、超时包装、后台任务、二进制与超大输出都返回了判词——但**返回判词不等于在该情形下正确**，
  我们没有覆盖 shell 命令空间的变异套件。它是审计层的概念验证，不是生产级沙箱。
